# 工程合同・费用・发票管理系统（Web 版）

Access 版的浏览器重写版：数据与业务逻辑一一对应，但**跑在 Linux（Debian / 飞牛 fnOS）上的 Docker 里**，
手机、平板、Windows、Mac 打开浏览器就能用，不再依赖 Microsoft Access。

> **当前版本：v1.12（正式版）** 　发布日期：2026-11-11
> 版本号显示在顶栏品牌位、登录页底部，以及「系统管理 → 参数设置 → 系统信息」。
> 升级方式：先备份数据，再 `docker compose up -d --build`（数据库只做增量迁移，不清数据）。

### 报价单怎么用

**报价 → 合同 → 送货** 是一条线，系统里也是连着的：

```
报价单（明细逐项录 / Excel 导入）──【转为合同】──▶ 合同（带出合同清单）
                                                     │
                                            【生成送货单】勾选本次送的项与数量
                                                     ▼
                                              送货单（导出 Word 打印签字）
```

1. **明细可以逐项加，也可以从 Excel 导入**：
   表单下半部分【报价明细】点【+ 添加一行】逐项录；
   或者点【下载导入模板】→ 在 Excel 里填好 → 回到页面底部【导入并追加】上传。
   模板里的列可以调顺序，程序按列名认（品名/品牌/型号/参数/单位/数量/单价/金额/含税/税点/备注），
   「合计」行和空行会自动跳过。**导入是追加，不会覆盖已经录好的行。**
2. **每一行自己标【含税 / 不含税】与【税点】**（0% / 1% / 3% / 5% / 6% / 9% / 13%）。
   表头不再有统一税率 —— 一张报价里既可能有含税项、也可能有免税项。
   新增行会默认带「含税 / 13%」，直接改就行。
   这两项的下拉选项在「基础资料 → 下拉选项」里维护（类目：含税方式、税点）。

   - **选了「不含税」，这一行的【税点】会自动变成 0%**（不含税就是不开票，税点没意义）。
     改回「含税」不会自动回填，要用 13% 还是 9% 自己选。
     这条规则**服务端也会执行一遍**，手工导入的数据同样跑不掉。
   - **明细上方有【批量设置】条**：先在下拉里选好要统一成的口径
     （【含税方式】和【税点】各一个，默认「（不改）」＝这一项不动），
     再点【应用到全部行】，一次把当前所有明细行刷成一样的。
     比如整份报价都不含税：选【含税方式】= 不含税 → 点【应用到全部行】，
     所有行的税点会自动跟到 0%，不用一行行改。
     没选的那一项不受影响（只想统一税点、不动含税方式也行）。
3. **数量 × 单价 = 金额**自动算（服务端也会再算一遍，前端算错了以服务端为准）；
   填了【优惠让利】，【报价总额】= 明细合计 − 优惠。
4. **品牌 / 型号 / 参数自动进「品牌型号库」**：
   录报价或合同清单时，只要填了品牌+型号，系统就把它收进库（连参数、单位、参考单价一起）。
   下次录单时**型号一选，品牌、参数、单位、参考单价自动带出来**。
   （规则：只补空缺，不会覆盖你已经维护过的参数。）
5. **报价状态可以在列表页直接改**：报价单列表的「状态」列是个下拉框，
   选完立即生效（草稿 / 已发出 / 已确认 / 已转合同 / 已作废），不用点进表单。
6. **导出美化 Excel**：报价单保存后，页面底部【导出报价单 Excel】——
   一张排版好的正式报价单（公司抬头、客户/项目/有效期、明细表，含税与税点各占一列、
   合计与**人民币大写**、报价说明、签字栏）。
7. **转为合同**：**管理员、财务，以及本单的经手员工**可以点【转为合同】。
   合同金额 = 报价总额，报价明细整份复制成【合同清单】，报价单状态自动变「已转合同」。
   同一份报价不能重复转（会提示已经转成哪张合同了）。
8. **合同清单**：合同表单里也能直接维护（同样支持 Excel 导入）。
   **付款和费用支出**里多了【对应合同清单项】明细：
   一笔付款/费用可以拆到多个清单项上（每行选一项 + 填本次金额），
   合计不能超过单据金额；这样能看出"这笔钱买的是哪几样东西"。
9. **生成送货单**：**在「合同管理」列表里，每行都有【生成送货单】按钮**
   （合同表单里也有）。点进去是一张勾选页：

   - 列出合同清单，带出**合同数量 / 已送 / 未送**；
   - **勾选这次要送的项**，【本次送货】默认就等于未送数量，可以改；
   - 顺手填收货人 / 电话 / 地址 / 送货日期 / 运输方式；
   - 点【生成送货单】→ 生成一张送货单，接着可以改、【导出 Word 送货单】打印签字。

   数量超过未送数量会自动按剩余量封顶；**送完的项不再出现**。
   同一张合同发几次货都可以（分批送货），合同表单下方会列出这张合同已生成的送货单。
   「送货单」不再单独占一个左侧菜单入口 —— 它属于合同的延伸。

### 列表页：点表头排序

每个列表页（发票、合同、付款、费用、往来单位、报价单、对私计算……）的**表头都能点**：

- 点一次 → 按这一列**升序**（表头出现 ▲，并变成主题色）；
- 再点一次 → **降序**（▼）；
- 没点过的列显示淡淡的 ⇅，意思是"这列也能排"；
- **排序写在网址里**（`?sort=unit_name&dir=desc`），可以直接收藏 / 发给同事，打开就是同一个顺序；
- 搜索、翻页、换每页条数**都不会把排序弄丢**，反过来也一样。

能排的列包括表里真实存在的字段，以及**算出来的列**——发票列表的「已核销 / 核销进度 / 收付状态」、
合同列表的「原件」、付款列表的「核销发票数」。点不了的表头就是纯文字（比如费用列表的「报销人」，
它不在费用表里，是联表带出来的），不会假装能点。

### 在多页列表里改东西，改完回到原来那一页

列表一页 25 行，翻到第 3 页改一条、删一条，**不会再被踢回第 1 页**：

- 点【编辑】进去，保存后点【返回列表】→ **还是第 3 页**（搜索词、排序也都还在）；
- 点【删除】→ 删完就停在第 3 页；
- 从第 3 页点【+ 新增】→ 存完也回到第 3 页；
- 列表里直接改的下拉（报价状态）本来就这样。


### 合同全景：一张合同到底怎么样了

**在合同管理列表里点「合同编号」**（不是点右边的编辑按钮），或者在合同表单上点
【合同全景（开票 / 收付款 / 利润）】，就能看到这张合同的全部关联业务：

- **首屏 8 张卡片**：合同金额 / 累计收款 / 累计付款 / 已开票（价税合计）、
  未结清发票（张数）/ 已登记费用 / **我方利润（对私「扣税」）** / **返还居间人**。
- **合同信息**：方向、类别、状态、项目、往来单位、签订日期、经手人、
  含税 / 不含税 / 税额、预付款与质保金比例、收付款方式……
  右上角还给了**粗略毛利（合同金额 − 已登记费用）**。
- **质保信息**：合同表单里多了一组字段 ——【质保开始】【保修期限(月)】【保修备注】。
  填了开始日期和月数，合同全景会自动算出**质保到期**，并提示「还剩 N 天 / 已过保 N 天」
  （剩余 90 天内标黄提醒）。个别设备或项目另有保修约定的，写在**保修备注**里
  （如「主机 3 年、辅材 1 年」），不影响上面的统一期限。
- **开票情况**：这张合同的每张发票（价税合计 / 已核销 / 未结清 / 状态）+ 合计行。
- **收付款记录**：按合同挂的每一笔收款与付款 + 合计行。
- **合同清单与送货**：逐项列出数量 / **已送 / 未送** / 单价 / 金额 / **已登记费用**。
- **对私结算**：这张合同涉及的对私单，以及**我方利润合计**与**返还居间人合计**。
- 另外还有送货单列表与合同附件。

权限照旧：**员工只能打开自己负责项目下的合同**，别人的合同会被挡回列表。

### 项目全景：一个项目的钱一次看完

**在首页「按项目经营情况」里点项目名称**（点项目编号也行），或者项目管理列表里点【项目全景】，
打开这张项目的全景页：

- **四张卡片**：收入合同额 / 累计收款 / 费用合计 / 预计毛利（含毛利率；没收入合同的标 ✳）；
- **四张卡片**：销项已开票合计 / 销项已收（已收讫）/ 未结清发票（张）/ 进项发票（成本）；
- **项目信息**：编号、业主、地点、项目经理、负责员工、开竣工、状态、预算；
- **合同**：这个项目的全部合同，点编号进「合同全景」；
- **销项发票（按合同分组）**：同一份合同的票在一组，组头写「合同编号 + 名称 +
  共几张 + 价税合计 + 已收讫 + 未结清」，每个合同一眼看清开了多少、还差多少；
  没挂合同的票单独一组排在最后；
- **进项发票（成本，按合同分组）**：同上，另外每张票带**费用类别**；
- **收付款记录（按合同分组）**：组头写「合同编号 + 名称 + 几笔 + 收款 / 付款小计」；
- **费用（按类别汇总）**：人工费 / 材料费 / 设备费… 每类的笔数、金额、已付、占比；
- **最近费用明细**：逐条费用的类别、摘要、金额、支付状态；
- 有对私结算的项目还有一块**对私结算**（我方利润 / 返还居间人）。

口径与首页那张表**完全一致**（同一套合计），只是把明细拆开展示；
员工只能打开自己负责 / 被授权的项目。

### 数据备份（系统管理 → 数据备份）

**一键备份**，页面右上角一个按钮：把「数据库 + 附件」打包存到飞牛的备份目录里。
备份时**不用停系统**，也不用你会敲命令。

- 备份内容：`app.db`（用 SQLite 在线备份 API 拿的**一致性快照**）、
  `manifest.txt`（完整性校验 + 逐表行数）、`uploads.tgz`（附件）。
  文件放在容器**外面**（飞牛上一个普通文件夹），可以直接拷走。
- 默认位置：`存储空间1` 上的 `/vol1/1000/backup/contract-app`
  （容器里是 `/backup/contract-app`）。页面上还有【换个位置备份】，
  可以填别的目录（**只能填在挂载进来的根目录底下**，不存在的文件夹会自动创建）。
- 每份备份都能【下载到本机】—— 浏览器的"另存为"由你自己选位置，
  这样就有了一份**不在 NAS 上**的备份。也能删掉旧的。
- **保留策略**：同一个目录里只留最近 `BACKUP_KEEP`（默认 14）份，超出的自动删最旧的。
- 文件名形如 `contract-app_20261010_214500_web.tgz`，与 `deploy/backup.sh`
  （命令行/crontab 版）**同命名、同结构**，两者可以混用。

**要备份到别的硬盘**（例如存储空间2），在 `docker-compose.yml` 里加一行挂载 +
把根目录加进 `BACKUP_ROOTS`，重建容器即可：

```yaml
    environment:
      BACKUP_ROOTS: "/backup,/backup-vol2"     # 允许写的根目录（逗号分隔）
    volumes:
      - /vol1/1000/backup:/backup
      - /vol2/backup:/backup-vol2             # 存储空间2
```

> ⚠️ 默认位置和数据库**在同一块盘**上（都在存储空间1）：盘坏了会一起没。
> 所以建议定期点一次【下载到本机】，或者按上面那样把备份放到另一块盘，
> 这才是真正"异地"的保险。

**万一要恢复**（页面最后一节也写着）：

```bash
tar xzf contract-app_xxx.tgz -C /tmp/restore     # 里面是 app.db / manifest.txt / uploads.tgz
docker compose stop
mv data data.broken.$(date +%F)                  # 现有数据留个底
mkdir data && cp /tmp/restore/app.db data/       # 放回数据库
tar xzf /tmp/restore/uploads.tgz -C data/        # 放回附件
docker compose up -d
```

### 台账 / 报表只显示你能看到的项目

查询统计里的台账、报表打印与导出（CSV / Excel）都按**账号的数据范围**过滤：

- 管理员 / 财务：全公司；
- 员工：只看自己负责（项目经理）或被授权项目的行 —— 和列表页、首页口径一致，
  不再是「列表只看自己、打印出来全公司」；
- 「费用类别统计」「往来单位台账」「出勤汇总」这类**没法按项目切分**的台账，
  员工账号直接看不到（需要的话让管理员换成能按项目看的台账）。

### 台账页是分页显示的

查询统计里的每张台账（以及 4 张报表页）**每页 200 行**（员工登录时结果已按项目过滤），右下角可以翻页、改每页行数
（100 / 200 / 500 / 1000），页码与筛选词会一直带着走。

> 「**打印**」和「**导出 Excel / CSV**」拿到的仍然是**全部行**，只是屏幕上按页看。

### 费用报销怎么用

**报销方式有三种**（«费用支出管理 → 报销方式»）：

| 报销方式 | 什么时候用 | 状态怎么走 |
| --- | --- | --- |
| **垫付报销** | 员工先自己垫钱，之后找公司报 | 待审批 → 已批准 → 已打款 |
| **预支核销** | 财务已经先打过备用金，从这笔预支款里抵扣 | 待审批 → 已批准 → 已打款（并计入预支单的核销） |
| **无需报销** | 这笔钱不用报销（公司直接付了 / 不涉及给谁打款） | 保存后直接是 **「无需报销」**，**不进审批待办** |

「**无需报销**」是 2026-10-10 按你说的加的，规则是：

- **不走报销审批**：不进「报销审批与打款」的待办，也不算「待审批 / 已批准待打款」的金额
  （这些口径都按状态取值，所以自动就对）；
- 但**钱照常计入**费用台账、项目成本、首页经营概览 —— 钱是真花了的；
- 三种方式**所有人都能选**（员工也能选）；
- 从「无需报销」**改回**垫付报销 / 预支核销时，状态会退回「待审批」重新排队
  （改报销方式不等于批准这笔单子）；「无需报销」的单子**打不了款**
  （只有「已批准」的才能打款）。

两种要动手的报销情形，都在「费用支出管理」里落地：

| 情形 | 操作 | 状态流转 |
| --- | --- | --- |
| **先给钱、后核销** | 财务在「费用报销 → 预支打款」登记 → **实际打款后点【确认打款】** → 员工在费用支出里选「预支核销」并选那张预支单 | 预支单：待打款 → 已打款 →（核销后）部分核销 / 已核销完 |
| **先自己垫、后报销** | 员工在费用支出里选「垫付报销」填单 | 待审批 → 已批准 → 已打款 |

- 填「预支核销」时会**校验可用余额**，超过余额直接拦下；
  且**预支单必须已确认打款**才能被核销——否则会出现"钱还没到手就先抵扣了"。
- 预支单状态：登记时是**「待打款」**，钱实际给到员工后由**财务**在编辑页点【确认打款】
  （一键落定并记录经办人）；**管理员只能查看，不经手打款动作**。
  之后「部分核销 / 已核销完」由核销情况自动判断。
- **打款方式**可选：银行打款 / 现金 / 微信 / 支付宝 / 其他。
- 员工提交的单据服务端强制记为「待审批」，**自己改不了**；管理员与财务录入的直接记为「已批准」（管理员不需要审批）。
- 登录后进首页会**弹出「我的费用报销情况」**（预支余额、待审批、已批准待打款、已打款），
  同一浏览器会话只弹一次；首页上也常驻一张同样的卡片。
- **「我的费用报销」只算人报上来的钱**：发票（进项）自动派生的那条费用虽然也是成本，
  但**不是谁垫的、也不是"待打款给某个人"**，所以不计入这里的汇总、明细和首页弹窗；
  它的金额仍然在「费用支出」与项目成本 / 经营概览里照常体现。
- 弹窗里的**「最近报销记录」只列还在流程里的单子**：已办结的「已批准」（等打款看上方数字）
  和「无需报销」（本来就不用报）不再重复列出；要看全部单据去「我的费用报销」页。

### 工资表：一键生成下月 + 封存

**月份下拉里只列「真正做过工资表」的月份**（外加你正在做的那个月），
不会再出现 1~8 月这种空月份空转。

**和「员工花名册」怎么联动**（花名册 = 发薪名单 + 工资标准的来源）：

| 情况 | 怎么做 | 结果 |
|---|---|---|
| **新入职** | 在「员工花名册」加一行 | 下个月生成工资表时自动就有他；本月也可以直接进工资表调整 |
| **离职** | 花名册里【状态】改成 **停用**，再填上 **【离职日期】**（别删这一行） | **离职当月**按在职天数自动折算；**之后的月份自动不再出现他** —— 不用手工去工资表里删人 |
| **离职日期还没到**（提前登记） | 同上，日期写实际离职那天 | 那个月及以前照常算，到了日子之后自然就不再出现 |

**离职当月怎么折算**：在职天数 = **离职日（含当天）**，
`基础工资` 与 `岗位津贴` × 在职天数 ÷ 当月自然天数；
出勤天数与餐补也只算到离职日；**加班费按完整月标准的时薪算**（不折算，那是签的工价）；
社保公积金与个税照常。折算比例会写在名字下面（例如 `2026-09-28 离职，当月按 28/30 天折算`），
逐人【调整】页里也有同样说明。

> 离职折算属于**当月规则**，跟考勤同级：**即使那个月之前已经定稿过，一填离职日期也会按天重算**
> （不这么做的话，先定稿、后补离职日期的人会一直挂着整月工资，看着就像"折算没生效"）。
> 不穿透的只有两种：**已封存**的月份（先填原因解锁），以及
> **你在【调整】里手工改过的那一行**。
>
> **手工改过的行永远以你填的为准**：保存后系统不再用折算把它盖回去
> （要恢复折算值，点工资表页的【整月按规则重算】）。
> 反过来，如果你**改了花名册的离职日期**，那一行会重新交给折算算 ——
> 因为日期变了，之前那个数是按旧日期折的。

> ⚠️ 做过工资表的员工**删不掉**（系统会拦下来并提示"月度工资表 N 条"）——
> 这是故意的：一删，历史月份的工资表就凭空少一个人。离职请一律用「停用」。
>
> 以前有个 bug：员工在花名册里一停用，他**以前所有月份**的工资行会跟着消失
> （数据还在库里，但页面和合计都少人）。现在只要那个月存过他的工资，就一直显示，
> 并且名字后面标一个「已停用」。

工资按月做，一次做一个月，滚动往下走：

1. **本月**：在「工资测算」里核对当月测算结果 → 点【生成本月工资表（定稿）】把结果存下来。
   （页面顶部和底部原来各放了一个按钮，其实是同一个动作，现在只留顶部那一个。）
   定稿后可以逐人【调整】；系统再测算不会覆盖你改过的数字。
   页面底部的【整月按规则重算】＝ 把本月所有人退回"没定稿"状态，按
   「花名册标准 + 当月考勤 + 离职折算」重算一遍（
   **手工调整的数字会被覆盖**），只在确实想推倒重来时用。
2. **生成下月**：点【一键生成下月工资表（YYYY-MM）】以本月为基准生成下个月 ——
   - **照抄本月的**：基础工资 / 岗位津贴 / 奖金 / 各项补贴 / 社保公积金 / 其他扣款 / 备注；
   - **按下月重算的**：加班费 / 餐补 / 出差补贴 / 计薪出勤天数（按**下月已批准的考勤**），
     个税跟着重算。
   生成后自动跳到下个月，在这个表上逐人【调整】。
3. **本月随即封存**：下个月的工资表一旦生成，本月就变成**只读**（行内不再有【调整】，
   直接访问调整页、或绕过页面直接提交也会被拦下）。
4. **确实要改封存月份的工资**：在工资表页填**原因**后点【填写原因并解锁】，
   解锁后才能改；改完点【改完重新锁定】收回去。
   每次解锁/重新锁定都记在审计里（谁、什么时候、什么原因），页面上一直看得到。

> 下个月已经有工资表时，【一键生成下月】不会覆盖它，只提示你直接切过去改。
> 另外页面上那个【整月按规则重算】（原来的"解除定稿"）和【填原因解锁】是两回事：
> 前者是把本月退回"测算中"（手工改的会被覆盖），只对**未封存**的月份有意义；
> 后者才是给封存月份放行。

### 出勤与工资测算

- **加班**：选完起止时间**即时算出时长**（支持跨夜，如 22:00→02:00 = 4 小时），
  也可手工改；**手工改过的数字不会被自动覆盖**，清空后可重新自动计算。
- **请假**：选完起止日期自动算天数（含首尾），并折算出小时；只请半天时把天数改成 0.5。
- **出差**：选完出发/回程日期自动算天数；**回程日期可留空**（按未定处理，天数记 0），
  回程后补填即**自动重算**。**补贴由系统按「天数 × 每日标准」自动算好入库**，
  填单时不需要填、页面上也不显示；想调每日标准请去「系统管理 → 参数设置」，
  算出来的补贴金额在出差单列表里能看到。
- 只统计**已批准**的记录参与工资测算。

### 工资表与工资条（按人社部计薪口径）

「工资管理 → 员工花名册」先录人 —— **工资名册和登录账号是分开的**：
不用本系统的员工照样能录进来发工资，录完即可参与测算与导出工资表。

```
月计薪天数 = 21.75 天（(365−104)÷12）        日工资 = 月工资 ÷ 21.75
小时工资   = 日工资 ÷ 8
加班费     = 加班小时 × 小时工资 × 倍数（周一至周六 1.5、周日 2.0、法定节假日 3.0）
请假扣款   = 请假天数 × 日工资 × 扣款倍数
出差补贴   = 出差天数 × 每日标准（出差单上已算好）
餐补       = 非出差出勤天数 × 15 + 出差天数 × 30
社保个人   = 缴费基数 ×（养老 8% + 医疗 2% + 失业 0.5%）+ 大病补充 10 元定额
公积金     = 花名册里登记的月缴额（个人承担部分）
个税       = 累计预扣法（起征点 5000 元/月 + 各人专项附加扣除）
应发小计   = 基础工资+岗位津贴+奖金+出海补贴+出差补贴+其他补贴+加班费+餐补+福利金+高温补贴
扣款小计   = 养老+医疗+大病补充+失业+公积金+企业年金+其他扣款+个税
实发工资   = 应发小计 + 其他补发 − 扣款小计
```

- 以上比例与标准**全部可以在「参数设置」里改**（政策调整时不用改代码）。
- **不缴社保**的员工（如退休返聘）在花名册里勾一下即可，个人部分自动记 0；
  社保基数留空或填 0 表示按基础工资计。
- 页面上：**生成本月工资表**（定稿）→ 逐人【调整】微调 → **导出工资表 / 工资条**。
  定稿后重新测算**不会覆盖**手工改过的数字；想整月推倒重来点【整月按规则重算】。
- 导出的 Excel 含两个工作表：**工资表**（一行一人，便于核算）与
  **工资条**（每人一块、带表头，打印后裁剪即可发放）。
- 只有花名册里**关联了登录账号**的员工，其已批准的加班/请假/出差才会自动汇总进工资。

### 记工（点工 / 临时工）

**这一套跟上面的「工资表」是分开的两套，互不影响**：工资表算正式员工（月薪 + 社保 + 公积金 + 个税）；
记工算工地上的点工、临时工 —— 干一天算一天，整天 / 半天结，没有社保个税。

**三步走**

1. **工人名单**（记工管理 → 工人名单）：姓名、工种、身份证号、**默认日工资**、
   **第二工资**（另一种活 / 双工的日薪，可以不填），身份证正反面照片在表单底部上传。
   走的人改成「停用」，**别删**（删了历史记工就缺人）。
2. **月度记工表就是日历，直接在格子上点，不用填表**（记工管理 → 月度记工表）：
   - **先在上方选项目**（或「未指定项目」）再点格子 —— 记工是按
     「日期 + 工人 + 项目」三条一起记的：一天分两个项目记（上午 A、下午 B）时，
     点 A 的格子只改 A 那一条，**不会把 B 的记录删掉重写**；
     「全部项目」是只读汇总视图（点格子会提示先选项目）——
   - 点一下＝**1 个工**（按默认日工资），再点＝**半天 0.5**，
     再点＝**2（按第二工资记一整天）**，再点＝**清空** —— 点完立刻存，不用按保存；
   - 每人自动按**自己的日工资**算钱，所以同一天不同人、价钱本来就不一样；
   - **某一天某人价钱不一样**（比如涨到 450）：**长按那个格子**直接填数 ——
     **只改这一天这个人**，其他天、其他人都不动，改过的格子标**橙色**；
     按第二工资记的格子标**蓝色**，一眼能和手工改价分开；
   - 电脑上还能**按住横向拖**，把一段日子一次记满（已经记过的自动跳过）；
   - 格子里的数字是**工天**；「2」是"按第二工资算的一整天"，**工天合计仍记 1 个工**。
     鼠标停上去能看到「日工资 × 工天 = 金额」。
3. **要一次给一批人记**（比如 6 号来了 6 个人）→ 点【批量记工】：选日期区间 + 勾人（可全选）→ 生成；
   **已经记过的那天自动跳过**，不会重复算钱。

> 记工没有单独的「明细列表」菜单了 —— 都在月表上点。要逐条改备注 / 传当天现场照片，
> 还是走 `/e/worklogs`（老链接仍然能用），只是左侧菜单里不再单列一项。

月表跟纸质记工本一个样子，**能直接打印给工人签字**（手工改价标橙、第二工资标蓝）。

**月底结算**：月表右上角点【生成本月人工费】—— 按项目汇总成一条「人工费」费用，
自动进「费用支出管理」并计入项目成本；**重复点只更新金额，不会重复记账**。
这条费用的报销方式是「无需报销」，所以不会跑到报销审批待办里去。

> 记工里没有的东西：不认识文字、不做人脸打卡。要的是"谁哪天干了多少，
> 双方认这份账"—— 真要留证，把当天的现场照片传到那条记工上（表单底部）。

### 发票怎么拖进来（PDF 自动录入）

在**发票管理**列表的**最上方**有个拖放区：**把电子发票的 PDF 拖进去**（一次可以拖多张），
系统会读出票面字段，**一张一张让你核对后保存** —— 不做"静默入库"，因为版式千差万别，
认不准的字段它宁可留空也不会瞎填。

**自动填进表单的**：

| 字段 | 怎么来的 |
|---|---|
| 发票号码 | 票面「发票号码」→ 同时用来**防重复录入** |
| 开票日期 | 票面「开票日期」 |
| 发票类型 | 票面标题（电子发票（增值税专用发票）→ 增值税专用发票） |
| **进项 / 销项** | 看购买方是不是本公司（也认纳税人识别号） |
| **对方公司** | 不是你方的那一方；能对上往来单位就自动挂上，对不上可**就地新建** |
| 价税合计 | 票面「（小写）」金额；**并与大写金额交叉核对**，对不上会提醒 |
| 税率 | 票面「税率/征收率」列，多个税率时取出现最多的并提示 |
| 不含税金额 / 税额 | 交给系统按公式重算（不采信 PDF 里的数字） |

**核对页上还有什么**：票面货物/服务名称（展开看）、大写金额、源文件名、
【看原件】（新窗口打开 PDF）、【跳过这张】、【结束导入】。

**PDF 原件不会丢**：保存后自动归档成这张发票的附件，发票表单底部和
「单据原件」页都能查看/下载。

**认不出来 / 不支持的**：

- **扫描件、手机拍照做的 PDF** —— 里面是图片、没有文字层，会明确告诉你"识别不了"（要上 OCR 才行）
- 改过扩展名的假 PDF、非 PDF 文件 —— 直接跳过并说明原因
- 同一张票拖第二次 —— 提示**已经录过**，并给出已有那张发票的链接
- 一次最多 30 张；临时文件 24 小时自动清理

**手机上（比如微信里收到的 PDF 发票）怎么导**：

1. 微信里**点开那张 PDF**（不是长按图标），右上角【…】→ **保存到手机**
   （有的版本是"用其他应用打开"→ 存到"文件"）；
2. 用**手机自带的浏览器**（华为浏览器 / Chrome）打开本系统并登录 ——
   **别用微信里直接点开的那个内置浏览器**，它在弹文件选择时容易卡住；
3. 进「发票管理」，点列表上方的**【选择文件…】**，在弹出的窗口里找
   「最近 / 下载 / 文件管理」里的那张 PDF（**一次可以选多张**）；
4. 系统读出票面字段 → 手指核对一眼 → 点**【保存，处理下一张】**。

> 手机上不用管那个"拖拽" —— **点【选择文件…】就行**，跟拖进去是同一个入口。
> 嫌手机上核对麻烦的话，也可以在微信里把 PDF 转发到「文件传输助手」，
> 在电脑上打开系统后直接拖进去。

> 想让进项/销项判断更准，可以去「参数设置」把**本公司的纳税人识别号**填上
> （不填就只按公司名称判断，一般也够用）。

### 首页的「累计付款」是怎么算的

**累计付款 = 「付款记录」里支出方向的付款 ＋ 「费用支出」里已付金额的合计。**

为什么这么算：你实际付出去的钱基本都记在**费用支出**里（付款记录只用来记收款和核销合同），
所以只统计付款记录的话，那个数永远是 0 —— 首页的累计付款卡片下面会把这个构成写出来
（`付款记录 X ＋ 费用已付 Y`），一眼能看出两个来源各是多少。

**费用的「已付金额」**（费用表单里新加的字段，列表也有一列）：

| 支付状态 | 已付金额 |
|---|---|
| **已支付** | **自动等于金额**（不用填） |
| **未支付** | 自动归 0 |
| **部分支付** | 自己填**实际付了多少**，只按这个数计入累计付款 |
| 不选状态 | 按你填的已付金额反推（填 0 → 未支付；填满 → 已支付；中间 → 部分支付） |

> **一句话**：一笔费用想让它算进「累计付款」，就把**支付状态选「已支付」**
> （或把已付金额填成实际付出数）。不选状态、也不填已付金额的费用**不计入** ——
> 那代表这笔钱还没付。费用列表的「已付金额」列会显示 0.00，一眼能看出哪些没算进去。

**为什么「已收讫」的发票不单独再加一次**：进项发票标「已收讫」时会**自动生成一条
「已支付」的费用**（见下一节），那笔钱已经通过费用算进累计付款了；
再加上发票金额就是重复计。

**未结清发票**同样只看真实的核销情况：状态是「已收讫」的票**不算未结清**
（钱都付清了），跟「未结清发票」台账口径一致。

### 进项发票会自动生成一笔费用

**只要录一张「收到进项发票」**（拖 PDF 进来、或手工新增），系统就会在
**费用支出**里自动生成一条对应的费用 —— 那笔采购就是项目成本，不用再手工抄一遍。

自动带过去的东西：

| 字段 | 取值 |
|---|---|
| 金额 | **发票的价税合计（含税）** |
| 发生日期 | 开票日期 |
| 项目 / 合同 / 往来单位 | 跟着发票走 |
| 费用类别 | **发票表单上的【费用类别】**（人工费 / 材料费 / 设备费…）。不选就按票面猜：服务 / 劳务 → 人工费，其余 → 设备费 |
| 摘要 | 「进项发票 + 发票号码 + 对方公司」，方便回头搜 |
| 对应合同清单项 | 票面品名能**唯一对上**清单项就自动对应（对上两个以上就不猜，留空）；没挂合同就留空 |
| 支付状态 | 发票状态是「已收讫」→ 已支付；否则未支付 |

> **发票的【关联合同】跟着【发票方向】走**：开具销项发票只能选**收入合同**，
> 收到进项发票只能选**支出合同** —— 前端下拉会按方向收窄，服务端保存时也会拦一道。
> 如果这张票只是某个项目上的采购、没有对应的支出合同，就**把关联合同留空**，
> 成本照样按【所属项目】归集，不影响成本与毛利。
>
> 老版本的发票没有「费用类别」字段：升级时会按它已经生成的那条费用的类别**自动回填**，
> 打开表单能看到，需要改再改。

**发票表单上就有【费用类别】**：收到进项发票时选这笔成本归哪一类（人工费 / 材料费 /
设备费 / 房租及住宿…），保存后自动生成的费用就用这个类别；发票列表也会显示这一列，
项目全景里按类别汇总的费用就分得清了。改类别只要改发票上的这一项，费用跟着同步。
**发票页下方有【对应的费用支出】面板**：看得到费用单号、金额、支付状态和类别，
可以改**对应合同清单项**，或者点【打开这条费用】去费用里改
（要一笔钱拆到多个清单项，就在费用里加明细行）。

**发票状态只有三个**，语义就是"这笔钱付没付"：

- **费用未付款** —— 票收到了，钱还没付
- **已收讫** —— 钱付清了 → 列表里的**收付状态直接显示「已结清」**（已核销＝全额、
  未结清＝0、进度 100%），「未结清发票」台账也不再出现它 —— 整个系统只有一套口径，
  不会出现"进度 0% 却已结清"的矛盾。进项发票还会把对应费用的支付状态变成「已支付」
  （**但要是这张票在付款记录里核销过，费用就保持「未支付」**——钱已经记在付款记录里了，
  两边都算会把首页「累计付款」算两遍）
- **已作废** —— 无效票 → 自动生成的费用会**一起删掉**

**核销满了会自动标「已收讫」（2026-10-11 起）**：以前得手工去发票页改状态下拉，
实际没人改，于是发票的「已收讫」状态一直是空的。现在只要在「付款记录」里
把一张票**核销满**（核销合计 ≥ 价税合计），这张票的状态就自动变成「已收讫」；
反过来把核销改小、或删掉那条付款记录，**系统自动标的**那个会退回「费用未付款」。
**人工在下拉里选过的状态一律不动** —— 系统只收回自己标的那个。

**删发票也会连带删掉它自动生成的那条费用**（并提示你删了哪一条）。
**销项发票（我们开给客户的）不生成费用** —— 只有进项才生成。

> 一生成就计入项目成本与收益（就是你选的口径）。所以**核对金额要在发票上核对**：
> 发票金额改了，这条费用会跟着改。

### 费用支出：对应清单项时「本次金额」不用再手填

在**费用支出**里加明细行、选好【对应合同清单项】后，**本次金额会自动带出这个清单项的金额**
（可以改成实际金额）。**就算你留空直接保存**，系统也会取清单项的金额，不会存成 0。

> 付款记录的「本次金额」**不自动带** —— 一笔付款常常只核销清单项的一部分，
> 那是要你按实际填的。

### 工程交付资料（基础资料 → 工程交付资料）

一个工程做完要交给客户的东西，集中登记在这一页：**IP 地址段** +
**每台设备（录像机 / 门禁主机 / 交换机…）的 IP、端口、用户名、口令** +
**点位图 PDF**。它单独占一个菜单项，**不在「基础资料」那排选项卡里**。

- **没有单独的「资料名称」** —— 名称就是下面填的这个项目，两种填法（二选一）：
  - 【对应项目】从「项目管理」里选一个 —— 用的是已有项目；
  - 或者直接在【项目名称】里**手写一个项目名** —— 这种**不会出现在项目管理里**，
    只在交付资料上显示（项目还没在系统里建档时用）。
  - 两个都填或都不填，保存时会拦住并提示。
- **IP 地址段可以写多段**：这个框是多行的，一行一段，例如
  `192.168.10.0/24（办公）` / `192.168.20.0/24（监控）` / `10.0.0.1 - 10.0.0.60（门禁）`。
- **设备一台一行**：设备名称 / 型号 / **IP 地址** / **子网掩码** / **网关** / 端口 /
  用户名 / 密码 / 备注，点【+ 添加一行】想加几台加几台。
  一个机柜 10 个摄像头**不必开 10 行** —— 在【IP 地址】里直接写范围
  `192.168.20.11-20` 就行；分属不同网段用「、」隔开（`10.0.0.11-13、10.0.1.11-13`）。
  列表里能看到每份资料有几台设备。
- **点位图**：保存后在页面下方【合同原件】处**上传 PDF**，手机上点开直接看。
- **交付时间自己选**（不是自动生成）。

> ⚠️ 这一页里的**设备口令是明文**，且跟着「基础资料」分组，**所有登录账号都能看到**。
> 如果只想让管理员/财务看，去 `meta.py` 的 `ITEM_ROLES` 里加一行
> `("e", "handovers"): ("admin", "finance")` 即可（菜单会自动隐藏，直接敲地址也会被拦）。

### 选发票时下拉里就能认出是哪张

**付款记录**里做发票核销时，发票下拉不再是光秃秃一串号码，而是
**「对方公司 ｜ 开票日期 ｜ 发票号码（价税合计）」**，比如：

```
客户一｜2026-06-25｜00000000000000000000（100,000.00）
```

顺序是刻意的：**越靠前越能认出是哪张票**。下拉框很窄，长标签一定会被截断，
所以把「公司 → 日期」放前面，最后才是那串没人记得住的发票号；
没填【往来单位】的票会退回成「日期｜发票号（金额）」。

选中之后，下拉下方还会**把「公司 · 开票日期 · 发票号码」完整写一行**，
不管屏幕多窄都能看全；再下一行是它**还剩多少可核销**。

**手机上这张表会自动改成「一票一张卡片」**（表格 6 列挤在 440px 里每列只剩几十像素，
下拉根本没法看）：表头收起，每个字段带自己的小标签竖排，
发票下拉占满整行，核销金额 / 比例并排。桌面端仍是原来的表格。

### 发票列表看得更清楚了

- 列表多了两列 **【对方公司】**（发票上的「往来单位」）和 **【所属项目】**——不用点进单据
  就知道这张票是开给谁的、算在哪个项目上（成本与毛利就是按「所属项目」归集的）；
- **搜索框也能按对方公司、按项目名搜**（输入客户名或项目名都能把相关发票筛出来）；
- 表头点一下就能**按对方公司 / 所属项目 / 发票号码 / 开票日期 / 价税合计 / 已核销 /
  核销进度 / 收付状态**排序；
- 发票状态只有三个：**费用未付款 / 已收讫 / 已作废**（＝这笔钱付没付）；
- **手机上发票列表自动变成"一张卡片一条"**（发票有 10 列，横着在手机上根本看不全）：
  每个字段竖着排一行，标签在值上面，右下角是编辑 / 附件 / 删除。

### 表单填写约定（三处与一般系统不同，都为了让单据"规矩"）

1. **单号不用填、也看不到**：项目编号、合同编号、各类单据号都由系统自动生成
   （如 `HT-0001`、`JB-0003`），表单里不再出现该字段，**列表页照常显示**。
   这样做是为了避免手工编号重复、断号。
   （例外：**发票号码/发票代码**是税局给的，仍需手工录入。）
2. **审批状态与审批意见不在申请时出现**：
   - 员工提交申请 → 服务端一律记为「待审批」，**自己改不了状态、也写不进意见**
     （即使绕过页面直接构造请求也没用）。
   - 管理员 / 财务 打开单据时这两个字段才可编辑，或者直接去「审批」页面批量处理。
   - 员工在申请单上能**只读看到**审批结果与审批意见。
3. **归属人固定为本人**：员工提交加班/请假/出差/报销时，"加班人 / 请假人 /
   出差人 / 报销人"自动带出当前账号，**不能替他人申请**。
   管理员与财务可以代员工录入。

计算口径（全部数字可在「系统管理 → 参数设置」里改）：

```
月计薪天数 = 每周工作天数 × 52 ÷ 12        （默认 6 天 → 26.00 天）
日工资     = 月工资 ÷ 月计薪天数            （默认 4500 ÷ 26 = 173.08）
小时工资   = 日工资 ÷ 每日工时              （默认 ÷ 8 = 21.63）
加班费     = 加班小时 × 小时工资 × 加班倍数   （默认 × 1.5）
请假扣款   = 请假天数 × 日工资 × 扣款倍数     （默认 × 1.0）
出差补贴   = 出差天数 × 每日补贴             （默认 40 元/天，出差单上已算好）
餐补       = 非出差出勤天数 × 15 + 出差天数 × 30
应发合计   = 月工资 + 加班费 + 出差补贴 + 餐补 − 请假扣款
```

**账号与权限（三种角色）**

定位一句话：**财务 ≈ 管理员，只少「用户管理」「登录日志」「参数设置」；
员工只留「自己经手」的功能。**

| 能力 | 管理员 admin | 财务 finance | 员工 employee |
| --- | :---: | :---: | :---: |
| 数据范围 | 全部 | 全部 | **仅自己负责的项目 + 管理员指定的项目，以及自己提交的单据** |
| 费用支出录入 | ✅（免审批） | ✅（免审批） | ✅（需审批） |
| 出勤申请（加班/请假/出差） | ✅ | ✅ | ✅（需审批） |
| 报销审批 / 出勤审批 | ✅ | ✅ | ❌ |
| **打款**（预支确认打款、报销标记已打款） | ❌（可查看） | ✅ | ❌ |
| 登记预支单 | ❌（可查看） | ✅ | ❌ |
| 工资与补贴测算 / 导出 | ✅ | ✅ | ❌ |
| 业务单据（合同/付款/费用/发票） | ✅ | ✅ | ✅（限自己项目） |
| 查询统计台账 / 打印 / 导出 | ✅ | ✅ | ❌ |
| 上传合同原件、在线预览、下载 | ✅ | ✅ | ✅（限自己项目） |
| 删除记录 / 删除附件 | ✅ | ✅ | ❌ |
| 下拉选项维护、费用类别管理 | ✅ | ✅ | ❌ |
| 参数设置 | ✅ | ❌ | ❌ |
| 用户管理 / 项目授权 / 页面权限 / 登录日志 | ✅ | ❌ | ❌ |

**员工看不到的四类东西**（左侧菜单直接不出现，**直接敲地址也会被 403 挡回**，
不是"藏起来"而已）：

1. **工资管理** —— 员工花名册、工资测算；
2. **查询统计** —— 合同台账、项目成本、发票台账等跨项目汇总视图；
3. **全员汇总表** —— 出勤汇总、预支款台账、报销台账（员工自己的额度与进度在
   「我的费用报销」里看得到，不需要看全员的金额）；
4. **系统管理** —— 用户管理、登录日志、参数设置。

- **项目负责员工**在「项目管理 → 负责员工」里指定；额外授权在「用户管理 → 项目授权」里勾选。
  两者取并集，就是该员工能看到、能录入的全部项目。管理员与财务不受此限制。
- **按账号开放 / 收起页面**（「用户管理 → 该账号 → 页面权限」）：
  角色只是"默认套餐"，具体到某个账号还能微调。每个页面 / 模块四档可选：

  | 档位 | 含义 |
  | --- | --- |
  | **默认** | 跟随角色本来的范围（多数情况保持这一档） |
  | **只读** | 强制可见，但只能看不能改（也可用来把某人本来能改的页面收成只读） |
  | **可编辑** | 强制可见，并且能新增 / 修改 / 删除 —— **员工要记工、录工人，就选这一档** |
  | **隐藏** | 强制收起 —— 连他本来能看的也收掉（如只让某财务录单据、不看全公司台账） |

  页面上有四列：**角色默认**（不看本页设置、只按角色算）、**实际生效**（保存后这个账号真正的样子：
  可编辑 / 只读 / 不可见）、**这个账号**（你选的档位），最左是页面名。
  保存后「实际生效」立即反映结果，一眼就能对上。
  左侧菜单、页面顶部选项卡、直接敲地址（403）三处同时生效，不是只藏菜单。
  「只读」那档页面顶部会出现只读提示，新增/编辑/保存按钮不显示，硬发写请求一律 403。
  「系统管理」（用户管理 / 登录日志 / 参数设置 / 数据备份）不参与配置，永远只有管理员；
  **管理员账号不受此页限制**（防止把自己锁在门外），要限制请先把角色改成财务或员工；
  配错了点「全部恢复默认」再保存即可；删除账号时这些配置随账号一起清掉。
  举例：让员工记工 —— 「月度记工表」「工人名单」都设成**可编辑**，他就能录工人、填日工资、在月表上点工天；
  只给「工资测算」设成**只读**，他看得到自己的工资测算但改不了。
- **打款动作归财务**：预支单的【确认打款】、报销单的【标记已打款】只有财务能执行
  （管理员可以看到审批情况与单据，但不经手资金动作）。
  审批（批准 / 驳回）管理员与财务都可以。
- **账号删除保护**：名下还有单据 / 预支 / 花名册记录的账号不允许删除（会提示
  改用「停用」），否则历史单据会变成查不到人的孤儿数据。停用后账号登不上，
  历史记录照样留着。
- 员工在个人类单据（预支/加班/请假/出差）里**只能看自己的记录**，看不到同事的。
- **入口**：登录后右上角 → 修改密码；管理员左侧「系统管理」→ 用户管理 / 项目授权 / 登录日志 / 参数设置。
- 用户名 3–32 位（字母/数字/下划线/点/@/连字符）；密码至少 8 位且需含
  大小写字母、数字、符号中的至少两类，并挡掉常见弱口令。
- 新建账号或管理员重置密码后，该账号**首次登录会被强制要求设置自己的密码**，之后才能用其他功能。
- 不能删除自己、不能停用/降级最后一个管理员，避免把自己锁在门外。

**登录防护（面向"连到外网"的场景）**

- 同一**账号**或同一 **IP** 在 15 分钟内失败 5 次即锁定 15 分钟（两把锁任一触发都拦），
  并在提示里给出剩余次数与等待时间；全部尝试（成功/失败）写入登录日志。
- 会话空闲 120 分钟自动失效；账号被停用后已登录的会话会立刻被踢出。
- Cookie 为 HttpOnly + SameSite=Lax；响应带 CSP、X-Frame-Options、nosniff 等安全头。
- **`X-Forwarded-For` 只在直连方是内网地址时才采信**，否则伪造这个头就能绕过按 IP 的锁定。
- 可选 IP 白名单：设 `ALLOW_IP_CIDRS=1.2.3.4/32,10.0.0.0/8`（留空不限制，本机永远放行）。
- 走 HTTPS 反代后打开 `FORCE_HTTPS=1`（http 自动 301）与 `SESSION_COOKIE_SECURE=1`。

> **要发布到外网？** 请先看 [`deploy/README.md`](deploy/README.md)：
> 三种方案（组网/隧道/直接映射）的取舍、Caddy 与 Nginx 的现成配置、
> 加固参数对照表、以及部署后的安全自检清单。核心一句：**能不映射端口就别映射**，
> 一定要映射就必须上 HTTPS —— 明文 HTTP 下密码在公网等于公开。

**金额逻辑**
- 合同 / 发票：只填 **含税金额** 与 **税率**，不含税金额与税额自动计算（含税 ÷ (1+税率)）。
- 付款 ↔ 发票 **多对多核销**：一行对应一张发票；填核销金额自动算比例，填比例自动算金额；
  支持一笔付款对多张发票、一张发票由多笔付款分次核销、按百分比部分付款。
- 保存前校验：单张发票累计核销不得超过其价税合计；核销合计不得超过本笔付款金额。
- 发票台账自动算出 **已核销 / 未核销 / 核销进度 / 收付状态**（未收付、部分收付、已结清）。

## 二、在飞牛 fnOS 上部署

前提：飞牛「应用中心」已安装并启用 **Docker**。建议在飞牛的存储空间里建一个共享文件夹，
例如 `/vol1/1000/docker/contract-app`，下面放本目录。

### 方式 A：图形界面（不敲命令，推荐新手）

1. **上传代码**：飞牛「文件管理」→ 进入 `docker/contract-app`，把本 `webapp` 目录里的所有文件上传进去
   （`app.py`、`meta.py`、`db.py`、`services.py`、`schema.sql`、`templates/`、`static/`、
   `requirements.txt`、`Dockerfile`、`docker-compose.yml`、`tools/`）。
2. **构建镜像**：飞牛 → Docker → 镜像 → 「构建镜像」 →
   路径选到 `contract-app` 目录，镜像名 `contract-app`，标签 `1.0` → 构建。
3. **创建容器**：Docker → 容器 → 「新增容器」→ 选 `contract-app:1.0`，容器名 `contract-app`；
   - 端口：容器 `8080` → 主机随便挑一个没被占用的，比如 `8080`；
   - 存储：主机 `<你的目录>/data` → 容器 `/data`，读写；
   - 环境变量（按需）：`ADMIN_PASS`、`SECRET_KEY`、`TZ=Asia/Shanghai`、`MAX_UPLOAD_MB=64`；
   - 勾选「开机自启」→ 创建。
4. 浏览器访问 `http://飞牛IP:8080`，用 `admin / admin123` 登录，**登录后立刻改密码**。

### 方式 B：SSH + Docker Compose（推荐，方便升级）

打开飞牛的 SSH（设置 → 终端与远程访问），然后：

```bash
cd /vol1/1000/docker/contract-app      # 换成你的实际路径
# 先改掉默认密码/密钥
vi docker-compose.yml                  # 修改 ADMIN_PASS 和 SECRET_KEY

docker compose up -d --build           # 首次构建并启动
docker compose logs -f                 # 看启动日志，Ctrl+C 退出查看
```

访问 `http://飞牛IP:8080`。之后升级只需 `docker compose up -d --build`。

### 方式 C：离线部署（飞牛拉不到镜像 / 无外网时）

在任意一台能联网、装了 Docker 的机器上（同架构：x86 或 ARM）：

```bash
docker build -t contract-app:1.0 .
docker save contract-app:1.0 -o contract-app.tar
```

把 `contract-app.tar` 传到飞牛，然后在飞牛 SSH 执行：

```bash
docker load -i contract-app.tar
# 再用方式 A 的「新增容器」，镜像直接选 contract-app:1.0
```

> 飞牛同时支持 x86 与 ARM（ARM 为公测）。基础镜像 `python:3.12-slim` 是官方多架构镜像，
> 两种设备都能构建。若你在 x86 上打了包拿到 ARM 上用，需要各自构建一次。

## 五、数据、备份与升级

- 所有数据都在 `data/` 目录：`app.db`（SQLite 主库）、`uploads/`（合同原件）。
- **备份推荐用网页上的【系统管理 → 数据备份】**（见上文）：不用敲命令，
  而且拿到的是一致快照、带完整性校验与行数清单。默认存到
  `/vol1/1000/backup/contract-app`，也能下载到本机。
- 想定时自动备份，用 `deploy/backup.sh`（与网页版同一套命名与结构）：
  ```bash
  # 飞牛上 root 的 crontab，每天 02:30（想改备份目录就加 BK_DIR=/vol2/backup）
  30 2 * * * /bin/sh /vol1/1000/docker/contract-app/deploy/backup.sh \
            >> /vol1/1000/docker/_backup/backup.log 2>&1
  ```
- 临时手工备一份也可以：
  ```bash
  tar czf contract-app-backup-$(date +%F).tar.gz -C /vol1/1000/docker/contract-app data
  ```
  （注意：WAL 模式下直接 tar 有可能拿到不一致的快照，应急可以、别当日常方案。）
- **升级**：覆盖代码 → `docker compose up -d --build`。数据库结构用 `CREATE TABLE IF NOT EXISTS`
  与增量迁移（只加列 / 只加索引），升级不会丢数据；`data/` 是挂载卷，也不会被镜像覆盖。

### 忘记密码

```bash
docker exec -it contract-app python tools/reset_password.py admin 新密码
```

## 七、常见问题

**Q：容器起来了但页面打不开？**
看日志 `docker compose logs contract-app`；再确认端口没被占用：
`netstat -tlnp | grep 8080`，被占用就改 `docker-compose.yml` 里的主机端口，例如 `"18080:8080"`。

**Q：上传大文件报错？**
调大环境变量 `MAX_UPLOAD_MB`（默认 64），改完 `docker compose up -d` 重建容器。

**Q：外网访问？**
用飞牛自带的 **FN Connect** 远程访问，或在飞牛里配反向代理并开 HTTPS。**不要把 8080 直接暴露到公网**
——本系统是内网办公定位，没有做防爆破、审计等安全加固。

**Q：多人同时编辑会冲突吗？**
SQLite 已开启 WAL，十几人规模的录入场景没问题。若并发很高（几十人同时写），
建议换成 PostgreSQL：改 `db.py` 的连接串并替换 SQL 中的少量方言即可，需要的话我可以帮你改。

**Q：报表想按项目分组小计 / 加页码？**
目前是平表台账 + 浏览器打印。可以做成分组报表（按项目小计、页脚页码），说一声即可。

**Q：能直接用手机录数据吗？**
可以。页面做了响应式，窄屏会自动收起左侧菜单。
